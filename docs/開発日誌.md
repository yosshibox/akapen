### 方針決定(発注者)
- **Akapen は独立したアプリケーション**(VEDA の一機能ではなく単体完結)。
- **性能で Rapture(Vector 配布のフリーソフト「おにぎり」)を上回る**ことが要件。Rapture の強みは描画エンジンではなく「起動ゼロ秒感=書き始めまでの総遅延が実質ゼロ」。よって Akapen の「上回る」は2軸: (1) 開く→一筆目の総遅延で負けない、(2) 書き味(筆圧・追従・非破壊・4K劣化なし)で圧倒。
- **GPU も CPU も駆使してとにかく高速・高レスポンス**。**Windows が主戦場**(mac も動く)。
- 仕様書を **第3版**へ改訂(§1 独立化・§6.1a Rapture 対照ベンチマーク・§6.2 実装勘所・§7 二本立て「機能は mac 先行/レイテンシ計測は Windows 先行」・§9/§10 反映)。

### コードレビュー所見(GPU a〜d + Phase0・要対応バックログ)
GPU コア描画をレビュー(条件付き APPROVE・重大なクラッシュ/データ破壊バグ無し・core 63/render 23 緑・当機 Metal で実走検証)。優先順:
1. **[重要・CONFIRMED] 半透明ストロークの自己重なりで GPU が alpha 累積**(`stroke.rs`/`bake.rs`): premultiplied source-over ゆえ同一ストローク内のキャップ/ジョイン/円ファン重畳部で alpha が濃くまだらに。CPU `raster.rs` は max-coverage 単一パスで均一。**opacity=1 では退化して一致**するため現テスト(全 opacity1.0)では非表面化。→ **M1 方針**: パレットは不透明色のみで opacity&lt;1 は UI 未提供のため、当面「**GPU 表示は opacity=1 前提**」を spec/コメントに明記。opacity&lt;1 を公開する版でマスク折り(オフスクリーン1回合成/stencil でカバレッジを1回に畳む)で対応。半透明パリティテスト(opacity0.5・自己交差線を CPU `flatten` と照合)を回帰項目として追加(現状は失敗するはず=有効)。
2. **[perf] `plan_bake` の Append が `last()` 前方消費で O(n)** → commit 毎に O(n²)。engine に最終確定ストローク直アクセサ or `next_back` で O(1) 化。
3. **[test] GPU 無し CI の動的スキップが「緑だが未検証」** → `AKAPEN_REQUIRE_GPU=1` で skip を失敗昇格する強制 GPU レーン。
4. **[perf] `composite_frame` が3 submit + 毎フレーム uniform/頂点バッファ新規** → 1 エンコーダ1 submit・uniform 常駐化。
5. **[移植性] NSView サーフェス生成はメインスレッド必須** → Phase e の FFI 配線でメインスレッド契約を明記(指示済)。
6. **[minor] `baked_tex` Nearest サンプリング**(ズーム/回転でエイリアス・細線消失)→ fit/zoom UI 時に mip/線形へ。背景 premultiplied 契約(透過背景でハマる)を要ドキュメント。`brush.opacity_for` は CPU/GPU 双方未使用(死にコード)。

**対応方針**: Phase e 完了後に「レビュー修正」タスクで 2・3・(1 のテスト+方針明記)・4 をまとめて適用(Phase e が render API へ配線中のため、API 変更を伴う修正は e 完了後)。

## 2026-07-12 — Windows GPU経路de-risk(Vulkanクラッシュの根本原因確定)

`cargo test -p akapen-render` がWindows実機(`yosshi@192.168.11.34`・Intel HD 620・ドライバ31.0.101.2112・2022/07/21付)で最初のGPUテスト直後に `0xc0000005 STATUS_ACCESS_VIOLATION` で全滅していた件、段階的probe(`crates/akapen-render/examples/gpu_probe.rs` 新規)で根本原因を確定した。

- **前提の誤り訂正**: `wgpu::InstanceDescriptor::new_without_display_handle()` は `WGPU_BACKEND` 環境変数を反映しない(`with_env()` を呼ぶ `*_from_env()` 系だけが反映。wgpu-types 30.0.0 `src/instance.rs`/`src/backend.rs` で確認)。かつ `Backends::default() == Backends::all()`。したがって過去3回の `WGPU_BACKEND=dx12/vulkan/gl` 切替は**実質すべて同一の `Backends::all()` 経路**を叩いていただけで、バックエンド切替は一度も効いていなかった。
- **単一バックエンドをコードで明示するprobeで切り分け**:
  - **DX12単体**: 列挙→adapter→device→triangle描画→背景テクスチャ描画→readback、全ステージ通過。**readbackパリティ完全一致(worst_diff=0)**。DX12は無罪。
  - **Vulkan単体**: 列挙・`request_adapter` は正常(Intel HD 620を正しく検出)だが、**`request_device`(vkCreateDevice相当)の直後に同一クラッシュ** `0xc0000005`。
  - **GL単体**: `request_adapter` が `NotFound`(surfaceless GLはdisplay handleなしでは列挙不可)でクリーンなRust panic。ドライバ側の問題ではなく想定内の制約。
  - **`all()`(クレートの実際のデフォルト)**: `request_adapter` がVulkanアダプタを優先選択し、DX12単体と同じ`request_device`で同一クラッシュ。**これが元の`cargo test`クラッシュの正体そのもの**と確定(後述のイベントログで同一fault offsetまで一致を確認)。
- **vulkaninfo単体実行(wgpu非経由)**: `--summary`・フル出力とも正常終了(exitcode 0、フルで1387行出力)。**Vulkan ICDの列挙・基本機能自体は健全**。クラッシュはwgpu-hal Vulkanバックエンドがデバイス生成時に叩く経路固有。
- **Windowsイベントログ(Event ID 1000, Application)で faulting module を特定**: probeのVulkanクラッシュも、元の`cargo test`のクラッシュ(`akapen_render-9940b787e740dd32.exe`)も、**完全に同一の faulting module `igvk64.dll`(Intel Vulkan ICD, バージョン31.0.101.2112)・同一 fault offset `0x000000000064ea72`・同一exception code `0xc0000005`**。Rust/wgpu側のバグではなく、**Intel純正Vulkanドライバ(igvk64.dll)内部でのアクセス違反**であることが確定した。

**結論**: 原因はRust/wgpu側ではなく、Intel HD 620(Kaby Lake世代)向けVulkan ICD `igvk64.dll`(ドライバ31.0.101.2112)内のバグ(デバイス生成時にクラッシュ)。DX12バックエンドは同一ハードウェアで完全に健全でreadbackパリティも完全一致するため、**「点列in→GPU描画→表示out」経路はDX12でWindows成立を実証済み**。次アクション案(要オーケストレーター/ユーザー判断):
1. Windows既定バックエンドを明示的にDX12優先(`Backends::DX12`、またはVulkanを除外した明示リスト)にする実装変更。
2. Intel Vulkanドライバの更新可否をユーザーに確認(このドライバは2022/07リリースで、より新しいドライバでigvk64.dll側のバグが修正されている可能性はあるが未検証・未実施)。

## 2026-07-12 — コールドスタート計測基盤(StartupTrace・段トレース・クロック注入)

Fable答申のスコープ厳守(段の遅延最適化そのものはしない、計測のみ)で「開く→一筆目」のコールドスタート経路に軽量トレースを配線した。

### 実装
- **`akapen-core::startup_trace`**(新規、外部crate不使用・`std::time`のみ): `StartupTrace` が `begin(name)`/`end(name)` で名前つきの段を記録し、`finish()` で開始時刻順の `Vec<(&'static str, Duration)>`(`Span`)を返す。不変条件: 未`end`の段が残っていれば `finish()` が `UnclosedSpans` を返す/同名段の二重 `begin` は `DuplicateSpanName` で拒否/`end` に対応する `begin` が無ければ `EndWithoutBegin`。`measure(name, f)` は begin/end を1回でくるむ便利関数。
- **クロック注入**: `StartupTrace::new(now: impl FnMut() -> Instant + 'static)` が任意のクロック関数を受け取る。実運用既定は `StartupTrace::new_with_system_clock()`(`Instant::now` を渡すだけ)。テストは1呼び出しごとに固定刻みで進む仮想クロックを注入し、順序・duration計算をGPU/実時間なしで決定的に固定。
- **ログ整形**: `format_spans(&[Span]) -> String` が「段名: X.XXXms」を1行/段で返す(`std`のみ)。
- **`akapen-render::startup`**(新規): `run_headless_cold_start`/`run_headless_cold_start_blocking` が実際のヘッドレスコールド経路を1回走らせながら7段を記録する — `instance_create` → `adapter_request` → `device_request` → `shader_compile_background`(`BackgroundPipeline::new`)→ `shader_compile_stroke`(`StrokePipeline::new`)→ `first_bake`(1x1 baked_tex へ1ストロークを焼き込み)→ `first_offscreen_frame`(background+baked_texを合成しreadback完了まで待つ)。段名は `COLD_START_SPANS_IN_ORDER` 定数で公開。**present/surface系(`SurfaceRenderer`/`GpuCanvas`のスワップチェーン取得・present)は今回配線せず、Session 1(実ウィンドウ添付)後追い** — 既存のヘッドレス経路(`Renderer::new_headless`/`OffscreenTarget`、既存テストや `gpu_probe` と同じ道)だけをなぞっている。

### 回帰テスト(絶対閾値なし、構造のみ固定)
- `akapen-core::startup_trace` 純テスト9件: 開始順記録・入れ子span・重複段名拒否・同名再利用可・`end`単独拒否・閉じ忘れ検出・`measure`・ログ整形・実クロックの単調性。すべて注入クロックで決定的。
- `akapen-render::startup` 1件(`cold_start_records_every_span_in_order_on_a_real_headless_gpu_path`): 実GPUで `run_headless_cold_start` を1回走らせ、7段全てが `COLD_START_SPANS_IN_ORDER` の順で記録されることを固定。`AKAPEN_REQUIRE_GPU` 作法に沿いGPU無し環境ではスキップ(`AKAPEN_REQUIRE_GPU=1`でハード失敗)。

## 2026-07-12(続) — コールドスタート計測基盤、gpt-5.6-terraレビュー指摘の反映

上記コールドスタート計測基盤(コミット 761b927)に対する gpt-5.6-terra レビューの指摘10件を反映した。

### 対応(High)
- **段のerror/panic-safe close**(`startup.rs`): adapter/device取得の各段で、await結果を一旦ローカル変数(`adapter_result`/`device_result`)に受けてから`end()`し、その後で`map_err`/`?`する形に変更。`?`の早期returnで`end`が飛び`UnclosedSpans`になる問題を解消。
- **first_bakeのGPU完了待ち**(`startup.rs`): `stroke_pipeline.draw`が内部で`queue.submit`した後、`device.poll(wgpu::PollType::wait_indefinitely())`で完了を待ってから`end(SPAN_FIRST_BAKE)`。bakeの実コストが`first_offscreen_frame`側へ混入するのを防止。
- **background_upload段の新設**(`startup.rs`): 「開く」の実コストであるbackground textureの生成/アップロードを独立span化。`run_headless_cold_start`/`run_headless_cold_start_blocking`に`background_size: (u32, u32)`引数を追加し、代表的な画像サイズを渡せる最小形に拡張(回帰テストは`(64, 64)`を使用)。

### 対応(Medium)
- **endのLIFO強制**(`startup_trace.rs`): `end(name)`は開いている段のうち最後(`open.last()`)の名前と一致必須。不一致は新設の`StartupTraceError::EndOutOfOrder(name, expected)`。入れ子はLIFOのみ許可(同名の再利用は引き続き許可)。
- **measureのpanic安全化**(`startup_trace.rs`): `catch_unwind(AssertUnwindSafe(f))`で捕捉し必ず`end`してから`resume_unwind`でpanicを伝播し直す形に変更。panic後もtraceが健全であることを回帰テストで固定。
- **開始順の契約整合**(`startup_trace.rs`): `begin`ごとに単調増加する`seq`を内部保持し、`finish()`は`seq`でソートしてから公開の`Span`列を返す(旧: close順push)。nestedテストの期待も「開始順(outer, inner)」に修正。
- **クロックにSend**(`startup_trace.rs`): `Box<dyn FnMut() -> Instant + Send>`に変更。await跨ぎ・spawn可能に。
- **逆行クロック検出**(`startup_trace.rs`): `saturating_duration_since`をやめ`checked_duration_since`を使用、`None`なら`StartupTraceError::ClockWentBackwards(name)`を返す。逆行クロックを注入する回帰テストを追加。
- **cold testの事前ウォーム排除**(`startup.rs`): テスト冒頭の`try_headless_renderer`呼び出し(=素通りのRendererを先に作ってGPU有無を確認するだけの処理)を廃止。`run_headless_cold_start_blocking`を直接呼び、その`NoAdapter`/`RequestDevice`を`AKAPEN_REQUIRE_GPU`のskip/hard-fail判定に使う形に変更。事前ウォームで隠れていた「真のcold経路」を検証する形に修正。
- **pipeline命名の限定**(`startup.rs`): headlessで計測するのはこのモジュールが独自に作る`BackgroundPipeline`/`StrokePipeline`のみで、画面(`GpuCanvas::attach`)側が別途持つscreen/bake用パイプラインとは別物である旨をコメントで明記。

## 2026-07-12 M1 主要ショートカット(コアキー写像)+ 回転到達性

比較地図 `docs/akapen-implementation-vs-roadmap-2026-07-12.md` の優先1(主要ショートカット)・優先2(回転到達性)に対応。

### コアにキー写像モジュール(`crates/akapen-core/src/keymap.rs`)
- 純関数 `resolve(KeyInput) -> Option<Action>`。**モード非依存**(Akapenは朱入れ専用なので単一写像=仕様§3.2)・OS型に非依存(SwiftUI/AppKitをimportしない=§7.1境界)。
